# 템플릿 검증 체크 (Template Completeness Check)

> 목적: 지금 모든 문서는 "체크리스트를 눈으로 보고 스스로 확인"하는 방식입니다.
> 사람은 바쁘면 빈칸을 건너뛰고 다음 단계로 넘어갑니다. 이 문서는 각 문서
> 유형별로 "이게 비어 있으면 다음 단계로 못 넘어간다"는 필수 필드를 명시해서,
> 나중에 간단한 스크립트로도 기계 검증할 수 있는 형태로 정리해 둡니다.

---

## §2. 검증 절차

```mermaid
flowchart TD
    A[문서 작성 완료 주장] --> B[§1 표의 필수 필드 확인]
    B --> C{빈칸 또는 '추후 작성' 존재?}
    C -- Yes --> D[다음 단계 진행 차단 - 작성자에게 반려]
    C -- No --> E[다음 단계 진행 허용]
```

## §3. 자동화 범위
- 현재는 사람이 §1 표를 기준으로 수동 점검
- 프로젝트 규모가 커지면 간단한 lint 스크립트(빈 `[ ]`/`[사람 작성]` 잔존 여부
  grep)로 전환 가능 — 별도 요청 시 구현
- **(선택) Claude Code 사용자**: `.claude/skills/harness-validate/` 스킬로
  이 §1/§3 검증을 대신 실행할 수 있습니다. 이 스킬은 그때그때 이 문서를
  직접 읽고 판정하므로, 표가 바뀌면 스킬도 자동으로 최신 기준을 따릅니다.
  스킬은 필수가 아니고, grep 한 줄로도 같은 효과를 낼 수 있습니다.
- **AC 모호성 검출**: TRD §5 AC 텍스트에 아래 같은 표현이 조건 없이 남아있으면
  "측정 가능한 조건으로 재작성"을 요구하고 다음 단계 진행을 차단한다.
  - 예시 금지어(구체적 수치/조건 없이 단독 사용 시): "적절히", "알아서", "충분히",
    "가능한 한", "잘 동작", "필요시"
  - 참고 grep(프로젝트 스택 확정 후 CI에 편입 가능): `grep -E "적절히|알아서|충분히|가능한 한" docs/trd/*.md`
  - 통과 기준: 위 표현이 아예 없거나, 있어도 바로 뒤에 구체적 수치/조건이
    붙어 있으면 허용 (예: "충분히 빠르게(200ms 이내)")
- **버전 헤더 동기화 검증**: `harness_00_definition.md`의 버전 배지(상단)·
  하단 푸터가 `harness_06_meta_improvement.md §1` 표의 최신 버전과 항상
  같은 값이어야 한다 — 다르면 색인 문서가 뒤처진 것(`harness_06 §3` "색인
  문서 버전 헤더 동기화 누락" 패턴, 2회 재발 이력 있음)이므로 다음 버전업
  작업을 "완료"로 보지 않는다.
  - 참고 grep(실행 확인됨, 2026-09-09 기준 셋 다 `v1.18` 일치):
    - 배지: `grep -oE "harness v[0-9]+\.[0-9]+" harness/harness_00_definition.md`
    - 푸터: `grep -oE "HARNESS-GUIDE · v[0-9]+\.[0-9]+" harness/harness_00_definition.md`
    - changelog 최신: `grep -oE "^\| v[0-9]+\.[0-9]+" harness/harness_06_meta_improvement.md \| tail -1`
  - 통과 기준: 세 값에서 뽑은 버전 번호가 전부 동일해야 한다.
  - **절차 편입**: `harness_06 §1`에 새 버전 행을 추가하는 작업 자체에
    이 3개 grep 재실행을 포함시킨다 — 별도 단계가 아니라 "버전업 완료"의
    정의에 포함시켜, 나중에 잊고 넘어가는 것을 구조적으로 막는다.

> 리뷰어가 자기 자신뿐인데 CODEOWNERS로 리뷰어를 강제 지정하는 건
