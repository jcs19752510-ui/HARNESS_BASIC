### CR-001: A1 TRD에 CSRF/세션 쿠키 보안속성 AC 반영
- 요청일 / 요청자: 2026-09-04 / 하네스 리뷰(보안 검토) → 프로젝트 담당자 승인
- 변경 대상 TRD: `docs/trd/attend_a1_trd.md` (상태: 확정 → 변경 후에도 확정 유지, 버전만 갱신)
- 변경 사유: 하네스 리뷰에서 세션 쿠키 인증(ADR-003) 채택 이후 CSRF 방어 정책과 쿠키
  보안 속성(HttpOnly/Secure/SameSite)이 어떤 문서에도 없다는 공백이 발견됨
  (`docs/attend_adr.md` ADR-006, ADR-007).
- 요청 내용 (Before → After):
  - Before: AC-1이 "세션 쿠키가 발급된다"까지만 검증. 로그아웃 등 상태변경 POST에
    CSRF 방어 없음.
  - After: AC-10(쿠키 보안속성 검증), AC-11(CSRF 없는 상태변경 요청 거부)을 §5에 추가.
    §2(로그아웃 API)에 csrf_token 파라미터 추가. §3 워크플로우에 CSRF 검증 단계 추가.
    §4 상태코드에 403(CSRF 실패) 추가.

| A1 로그인/인증 | 미착수(코드 없음, TRD만 확정) | AC 2건 추가, API/워크플로우/상태코드 소폭 확장 | 재작업 아님 — 최초 구현에 바로 반영 (코드가 아직 없어 재작업 비용 없음) |
| A2~A6 | 미착수 | 향후 상태변경 POST 전부 CSRF 토큰 필요 — `docs/attend_tech_conventions.md` §3에 이미 전역 규칙으로 반영됨 | 해당 없음(사전 반영) |

## 처리 결과
- 승인: 프로젝트 담당자 (2026-09-04, 세션 내 "계속 진행해줘"로 승인)
- 반영 완료: `docs/trd/attend_a1_trd.md` v1.1로 갱신, `docs/attend_adr.md` ADR-006/007 "승인됨"으로 갱신
- A1은 아직 코드 구현 전 단계였으므로 별도 재작업 브랜치 없이, 이번 CR을 반영한 스펙으로
  바로 최초 구현을 진행함 (`harness_12 §5`의 "완료된 단위 재작업" 규칙은 미적용 — 완료된
  단위가 아니었기 때문).
