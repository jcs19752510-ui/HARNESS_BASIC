## §1. 적용 법령/근거 [사람 작성 — 법무 검토 권장]
- 대상: 미성년 학생 본인 연락처(`contact`) + 법정대리인(보호자) 연락처(`guardian_contact`)
- 관련 법령 후보: 개인정보보호법(대한민국) — 미성년자 개인정보는 통상 법정대리인 동의 요건이
  더 엄격하게 적용됨. **AI는 이를 법률 자문으로 단정하지 않으며, 실제 적용 여부는 사람의
  법무 검토가 필요합니다.**
- 이 조직이 개인정보보호법상 어떤 처리자 유형(소규모 조직 특례 대상 여부 등)에 해당하는지도
  사람이 확인해야 확정 가능한 항목입니다.

## §2. 데이터 항목별 보존기간 — 결정 완료 (2026-09-05, ADR-008)

| 데이터 항목 | 민감도 | 현재 스키마 상태 |
|---|---|---|
| `students.contact` (학생 연락처) | 높음 | 평문 컬럼 — 목록 마스킹/상세 전체+열람로그 방식 확정 |
| `students.guardian_contact` (보호자 연락처) | 높음 | 위와 동일 |
| `students.*` 기타(이름/학년/사진 등) | 중간 | `use_yn` 소프트삭제만 적용 (변경 없음) |

**결정 (후보 B 채택):**
- **화면 노출**: 목록 화면에서는 `010-****-1234`처럼 뒷자리만 마스킹. 상세 화면에서
  전체 번호를 조회할 때마다 열람 이력(조회자/일시/대상 학생)을 신규 테이블에 기록한다.
  → **후속 작업**: `attend_a0_datamodel_trd.md`에 열람 이력 테이블(가칭
  `contact_view_log`) 추가 — A2 착수 전 선행 TRD 갱신 필요 (아직 미반영, §4 참조).
- **보존기간**: `use_yn='N'`(전학/졸업 등 비활성화) 시점 기준 **3년**간 유지 후 연락처
  필드를 물리적으로 익명화(`****`)한다. **3년은 "교육기관 관례" 기준 잠정치이며, 정확한
  법정 보존기간은 §1의 법무 검토 후 조정 가능.**
- 기존 "역할별 접근 범위: 전체 개방" 확정 사항(요구사항 정의서 §3)과는 충돌하지 않음
  (역할이 아니라 화면 위치·열람 여부로 통제하는 방식이기 때문).

## §3. 파기 절차
`harness_10` §3의 표준 흐름(트리거→대상목록→승인→파기→로그) 적용. 트리거는 "전학/졸업으로
`use_yn='N'` 처리 + 3년 경과". 실제 파기 배치 작업 구현·승인자 지정은 A2 이후 별도
작업지시서로 구체화 예정(아직 미착수).

## §4. 열람/정정 요청 처리 절차
현재 A1~A6 TRD 어디에도 "보호자가 직접 열람/정정을 요청하는 화면"은 범위에 없음 (교사가
대신 입력/수정하는 구조). 보호자 셀프서비스 화면이 없다면 이 절차는 "보호자가 담임교사에게
요청 → 교사가 학생정보 화면에서 수정"하는 수동 절차로 대체 가능 — **이것도 범위 확인이 필요한
사람 결정 사항**(요구사항 정의서에 명시적으로 없던 내용이라 임의로 화면을 추가하지 않음).
