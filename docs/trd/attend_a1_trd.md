# TRD — A1 로그인/인증

- 프로젝트: 학생 출결 등록 프로그램
- 단위: A1 로그인/인증
- 상태: 확정

---

## §0. 범위 및 흐름 개요
- 역할: 관리자/담임교사/임원교사/교역자 4개 역할 공통 로그인 화면 1개
- 흐름: 로그인 화면 → 아이디/비밀번호 입력 → 검증 → 세션 발급 → 메인 화면 리다이렉트
- 이 단위가 의존하는 선행 단위: 없음 (최우선 착수 단위)
- 이 단위에 의존하는 후행 단위: A2~A6 전체 (모든 화면이 로그인 세션을 전제로 함)

## §0-1. 비기능 요구사항 체크
- **동시성:** N/A (로그인은 사용자별 독립 세션이라 충돌 대상 아님)
- **권한:** 로그인 성공 시 `users.role`을 세션에 저장, 이후 화면에서 참조. 이 단위 자체는 역할 구분 없이 공통
- **감사(audit):** 로그인 성공/실패 이력은 이번 단위 범위 밖 (요구사항 정의서상 감사추적은 "출결 기록 변경"에 한정, 필요 시 별도 단위로 확장 검토)
- **개인정보:** 비밀번호는 평문 저장/전송 금지, 해시(bcrypt)만 저장
- **삭제 정책:** N/A

## §1. 데이터 구조
`attend_a0_datamodel_trd.md`의 `users` 테이블 재사용 (신규 테이블 없음)

| 컬럼 | 타입 | 비고 |
|---|---|---|
| id | PK | |
| username | VARCHAR UNIQUE | |
| password_hash | VARCHAR | bcrypt 해시 |
| name | VARCHAR | |
| role | ENUM | 관리자/담임교사/임원교사/교역자 |
| use_yn | CHAR(1) | 'N'이면 로그인 차단 |

세션 저장: 서버 메모리 또는 DB 세션 테이블 대신, **서명된 쿠키(signed cookie)** 방식 사용
(FastAPI의 `SessionMiddleware` + `itsdangerous`). 별도 세션 테이블 불필요.

## §2. 함수/API 명세

| 엔드포인트 | 입력 | 출력 | 설명 |
|---|---|---|---|
| GET /login | - | 로그인 폼 HTML | |
| POST /login | username, password | 성공: 세션쿠키+메인화면 리다이렉트 / 실패: 에러메시지+폼 재표시 | |
| POST /logout | - (세션쿠키) | 세션 무효화+로그인화면 리다이렉트 | |
| (미들웨어) 인증 체크 | 모든 보호된 경로 요청 | 세션 없으면 /login으로 리다이렉트 | A2~A6 공통 적용 |

## §3. 워크플로우 및 비즈니스 로직

**정상 흐름:**
1. 사용자가 `/login`에서 아이디/비밀번호 입력, 제출
2. 서버가 `username`으로 `users` 조회, `use_yn='Y'`인지 확인
3. `password_hash`와 대조 (bcrypt.verify)
4. 일치하면 세션 쿠키 발급(만료 30분, 활동 시 자동 연장), 메인 화면으로 리다이렉트
5. 일치하지 않으면 "아이디 또는 비밀번호가 올바르지 않습니다" 메시지와 함께 로그인 화면 재표시 (아이디 존재 여부는 노출하지 않음 — 계정 존재 유추 방지)

**예외 상황:**
- 존재하지 않는 아이디 → 위와 동일한 일반 에러 메시지(계정 유무 노출 금지)
- `use_yn='N'`(비활성 계정) → 일반 에러 메시지와 동일하게 처리 (비활성 여부 노출 금지)
- 세션 만료 후 보호된 페이지 접근 → `/login`으로 리다이렉트, 원래 가려던 경로는 로그인 후 이동(선택 구현)
- 로그인 실패 횟수 제한: **없음** (요구사항 확정사항)

## §4. 상태/에러 코드

| 코드 | 의미 | 발생 조건 |
|---|---|---|
| 200 | 로그인 성공 | |
| 401 | 인증 실패 | 아이디/비밀번호 불일치 또는 존재하지 않음 또는 비활성 계정 (구분 없이 동일 응답) |
| 302 | 미인증 접근 시 리다이렉트 | 세션 없이 보호된 경로 접근 |

## §5. 인수 조건 (AC)
- [ ] AC-1: 올바른 아이디/비밀번호 입력 시 로그인 성공, 세션 쿠키가 발급되고 메인 화면으로 이동한다
- [ ] AC-2: 틀린 비밀번호 입력 시 401과 함께 일반 에러 메시지가 표시되고, 아이디 존재 여부가 노출되지 않는다
- [ ] AC-3: 존재하지 않는 아이디 입력 시 AC-2와 동일한 메시지가 표시된다 (구분 불가)
- [ ] AC-4: `use_yn='N'`인 계정은 올바른 비밀번호를 입력해도 로그인이 거부되고, AC-2와 동일한 메시지가 표시된다
- [ ] AC-5: 비밀번호는 DB에 평문으로 저장되지 않는다 (해시만 저장 확인)
- [ ] AC-6: 로그인 세션은 30분간 활동이 없으면 만료되어 재로그인이 필요하다
- [ ] AC-7: 로그인 세션이 없는 상태로 보호된 경로(A2~A6)에 접근하면 로그인 화면으로 리다이렉트된다
- [ ] AC-8: 로그인 실패 횟수에 제한이 없다 (연속 실패해도 계정이 잠기지 않음을 확인)
- [ ] AC-9: 로그아웃 시 세션이 즉시 무효화되어, 이후 보호된 경로 접근 시 재로그인이 요구된다

## §6. 테스트 시나리오

| 시나리오 | 입력/조건 | 기대 결과 | 대응 AC |
|---|---|---|---|
| 정상 로그인 | 올바른 username/password | 세션 발급, 메인화면 이동 | AC-1 |
| 비밀번호 오류 | 존재하는 username + 틀린 password | 401, 일반 에러 메시지 | AC-2 |
| 존재하지 않는 계정 | 없는 username | AC-2와 동일한 메시지 | AC-3 |
| 비활성 계정 | use_yn='N' 계정 + 올바른 password | AC-2와 동일한 메시지 | AC-4 |
| 세션 만료 | 로그인 후 30분 이상 미활동 후 페이지 접근 | 로그인 화면으로 리다이렉트 | AC-6 |
| 미인증 접근 | 세션 쿠키 없이 /students 등 접근 | /login으로 리다이렉트 | AC-7 |
| 반복 실패 | 같은 계정으로 10회 이상 실패 | 잠기지 않고 계속 시도 가능 | AC-8 |
| 로그아웃 | 로그인 후 /logout 호출 → 보호경로 재접근 | 재로그인 요구됨 | AC-9 |

## §7. 미결 항목

| 항목 | 권장 기본값 | 확정 필요 여부 |
|---|---|---|
| 로그인 실패 시도 로깅 여부(감사 목적은 아니고 보안 모니터링용) | 우선 구현 안 함, 필요 시 추후 단위로 추가 | 낮음 — 진행하며 판단 |
