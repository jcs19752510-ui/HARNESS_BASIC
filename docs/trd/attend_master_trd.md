# 학생 출결 등록 프로그램 — 마스터 TRD (전체 화면/실행 순서)

> 요구사항 정의서(attend_requirements_summary.md), 데이터모델(attend_a0_datamodel_trd.md),
> 환경설정(attend_env_setup.md)을 기반으로 전체 실행 단위를 정의합니다.
> 순서는 "화면이 보이는 순서"가 아니라 "위험도/의존성 순서"입니다.

---

## 1. 전체 화면/기능 목록

| 단위 | 이름 | 핵심 기능 |
|---|---|---|
| A1 | 로그인/인증 | 아이디/비밀번호 로그인, 세션 관리 |
| A2 | 사용자(교사) 관리 | 관리자가 교사 계정 생성/역할(4단계) 지정 |
| A3 | 연도/반 관리 | 연도별 반 생성, 반-교사 배정(다대다) |
| A4 | 학생 관리 | 학생 등록, 사진 업로드, 반 배정/반이동 |
| A5 | 출결 등록 (핵심) | 반별 일괄 출결 등록, 동시 저장 처리 |
| A6 | 출결 수정/이력 조회 | 개별 수정, 감사 이력(누가/언제/뭘 바꿨는지) 조회 |
| A7 | 출결 현황/통계 | ✅ 범위 포함 확정 (2026-09-05) — 관리자용 "전체(모든 반) 현황 대시보드" 1개 화면. 반별/학생별 세부 통계는 이번 확정 범위 밖(추후 필요 시 별도 논의) |

## 2. 실행 순서 및 근거 (위험도/의존성 기준)

```
A1 로그인/인증
   └─ A2 사용자(교사) 관리      ← A1의 users 테이블에 의존
        └─ A3 연도/반 관리       ← A2의 교사 계정에 의존(반-교사 배정)
             └─ A4 학생 관리      ← A3의 반에 의존(반 배정)
                  └─ A5 출결 등록  ← A4의 학생+반에 의존, 프로젝트의 핵심 기능
                       └─ A6 출결 수정/이력 조회
                            └─ A7 출결 현황/통계 (전체 대시보드)
```

**순서 근거:**
- 인증(A1)이 없으면 다른 모든 화면이 "누가 접근하는지" 판단 불가 → 최우선
- A2~A4는 "마스터 데이터"로, A5(출결 등록, 프로젝트의 진짜 목적)가 의존하는 선행 조건
- A6(수정/이력조회)은 A5와 데이터 구조를 공유하므로 A5 직후 배치
- A7(통계)은 A5/A6의 `attendance` 데이터를 집계만 하는 조회 전용 화면이라 마지막 배치 (2026-09-05, 범위 포함 확정 — 요구사항: 관리자용 전체 반 현황 대시보드 1개)

## 3. 각 단위의 데이터모델 대응

| 단위 | 관련 테이블 |
|---|---|
| A1 | users |
| A2 | users |
| A3 | years, classes, class_teachers |
| A4 | students, student_class_history |
| A5 | attendance, attendance_history |
| A6 | attendance, attendance_history |
| A7 | attendance, classes (집계 전용 — 신규 테이블 없음) |
